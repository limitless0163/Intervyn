# COMMENT_INSTRUCTIONS.md

Review the project code and add only necessary, concise, engineering-quality comments and documentation.

## Requirements

- **All newly added or rewritten code comments and docstrings must use Chinese.**
- Add comments only where they improve understanding. Do not comment every line or obvious code.
- Keep comments concise and focused on the most important information.
- Add appropriate documentation for important classes, functions, methods, modules, and non-obvious parameters or return values.
- Add comments for complex logic, important design decisions, edge cases, constraints, or code whose purpose is not immediately clear.
- Prefer explaining **why** something is done rather than simply describing **what** the code does.
- Do not add comments to trivial assignments, obvious control flow, simple wrappers, or self-explanatory code.
- Follow standard comment and docstring conventions for each language and framework, while keeping the comment content in Chinese.
- Keep newly added comments consistent with existing comments in style, formatting, structure, and level of detail.
- If existing comments are inconsistent, non-standard, redundant, outdated, misleading, or overly verbose, normalize them when appropriate.
- Do not modify program behavior, APIs, architecture, or business logic solely for commenting purposes.

Goal: make the code easy for developers to understand while keeping comments **Chinese, concise, necessary, standardized, and uncluttered**.
